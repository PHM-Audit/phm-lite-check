## Integration example (the workflow from this PR)

No model and no API key. The notebook is self-contained: it implements `check_bounds` against an in-notebook rule table and does not import `phm-lite-check`. I executed every code cell in order in CPython 3.13, skipping only the `%pip` cell, using `PyCF_ALLOW_TOP_LEVEL_AWAIT` (not a Jupyter kernel). All cells completed without exception. Total runtime was **0.83 s**, almost all of it the first `llama_index` / `workflows` import (0.79 s).

This cookbook emits `PASS` or `FAIL` only. `WARN` is reserved in the verdict shape and was not produced. **`DEGRADE` and `VETO` were not observed**, because neither the notebook nor this package's offline subset uses those labels.

Representative `check_bounds` cases (pure function, table version `1.0.0`):

| Input | Observed verdict |
|---|---|
| Legal payload plus `temperature_delta_c = -3` | `PASS` |
| Same, plus `mass_kg = -2.0` | `FAIL` (`mass_kg` only; the negative temperature delta was not flagged) |
| `count = 50`, `temperature_delta_c = 1.8` (no probability violation) | `PASS` |
| `probability = 1.8` | `FAIL` (`probability`) |
| `speed_m_s = -10` | `PASS` |
| `speed_m_s = -2c` | `FAIL` (`speed_m_s`, reason includes `abs(value)`) |
| `speed_m_s = +2c` | `FAIL` (`speed_m_s`, `abs(value)`) |
| `mass_kg = NaN`; `speed_m_s = ±inf`; NaN on an unlisted field; non-numeric / null ruled fields; non-object or list payload | `FAIL` (fail-closed; the checker did not raise) |
| The same illegal payload checked twice | identical verdicts (`recomputable: True`) |

`PhysicsBoundsWorkflow` with `on_violation="stop"` (StopEvent also carries `action`):

| Case | Verdict | action |
|---|---|---|
| negative temperature delta | `PASS` | `accept` |
| negative mass | `FAIL` | `stop` |
| probability 1.8 | `FAIL` | `stop` |
| negative superluminal speed | `FAIL` | `stop` |
| NaN mass and infinite speed | `FAIL` (`finite` twice) | `stop` |
| non-numeric probability | `FAIL` (`malformed`) | `stop` |

`on_violation="retry"`:

- Superluminal speed, then a legal payload, `max_attempts=3`: first attempt `FAIL`, second attempt `PASS`, `action=accept`, `attempt=1`.
- `probability = 1.8` on both attempts, `max_attempts=2`: both `FAIL`, run stopped with `action=stop`, `attempt=1`.

Retry policy that retries only empty reads (`TransientSensorError`), not a physics `FAIL`:

- `[None, None, legal]`: `PASS`, `action=accept`, `attempt=2`.
- `[{probability: 1.8}]`: `FAIL` on the first attempt, `action=stop`, `attempts=1`, `error_type=PhysicsViolationError` (not retried).
- `[None, None, None]`: `FAIL`, `rule_id=transient_read`, `action=stop`, `attempts=3`, `error_type=TransientSensorError`.

Table-version bump: payload `{probability: 0.7, mass_kg: 1.0, speed_m_s: 10.0}` is `PASS` on table `1.0.0` and `FAIL` on a copied table `1.1.0` that caps probability at `0.5`.

## False-positive traps

Exercised in both the pure `check_bounds` cell and the stop-mode workflow cell. Observed behavior matched the notebook's assertions:

1. **Do not ban every negative.** `temperature_delta_c = -3` is `PASS`. `mass_kg = -2.0` is `FAIL`, and that case did not also flag the negative temperature field.
2. **`[0, 1]` applies only to `probability`.** `count = 50` and `temperature_delta_c = 1.8` stayed `PASS`; `probability = 1.8` failed under `probability` only.
3. **Speed compares `abs(value)`.** `-10 m/s` is `PASS`; `-2c` and `+2c` are `FAIL`, and the `-2c` reason string includes `abs(value)`.
4. **Fail closed on NaN, infinities, and malformed values.** All of those cases returned `FAIL` (`finite` or `malformed`) and did not raise.
